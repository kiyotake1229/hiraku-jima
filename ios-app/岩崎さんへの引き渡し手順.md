## 1. アプリ概要

| 項目 | 内容 |
|------|------|
| アプリ名 | ひらく島 |
| Bundle ID | `work.ltv.hiraku` （変更する場合は 4章参照） |
| 構成 | Capacitor 7（WebView同梱型ネイティブアプリ）。本体は1つ上のフォルダの `index.html`。3D描画ライブラリ three.js r128 もアプリ内に同梱 |

### どんなアプリか

森を切り開いて家を建て、集落 → 村 → 町 → 都市 → 大都市へ育てる3D箱庭ゲームです。
地面を自由な色で塗り、毎日開くとログインボーナスと日替わりの「今日のおねがい」が届きます。
達成すると星がもらえ、星で特別な建物や4つの世界（魔法の国・和風の城下町・未来都市・海底都市）をひらけます。

## 2. 必要な環境

- macOS（Xcode 15 以降が動くバージョン）
- Xcode（App Store からインストール。初回起動時に iOS プラットフォームの追加を求められたら追加する）
- Node.js 18 以降（`node -v` で確認）
- CocoaPods（`brew install cocoapods`。`pod --version` で確認）

## 3. ビルド手順

このフォルダ（`ios-app/`）をターミナルで開き、以下を順に実行してください。

```bash
# 1) 依存パッケージを取得（Dropbox を軽くするため node_modules は削除してあります。必ず最初に実行）
npm install

# 2) Web本体をコピーし、iOSプロジェクトに反映（CocoaPods も自動で実行されます）
npm run sync

# 3) Xcodeで開く
open ios/App/App.xcworkspace
```

> **注意**: 必ず `App.xcworkspace` を開いてください（`App.xcodeproj` ではありません）。
> `npm run sync` の最後に `xcodebuild ... clean` が失敗したと出ても、Pods の統合は終わっているので問題ありません。

---

## 4. Xcode上での署名設定

1. 左ペインで **App** を選択 → **Signing & Capabilities** タブ
2. **Team** に自社の Apple Developer アカウントを選択（"Automatically manage signing" は ON）
3. 必要に応じて **Bundle Identifier** を自社のものに変更（変更した場合は `capacitor.config.json` の `appId` も合わせてください）
4. **General** タブで **Version**（例: 1.0.0）と **Build**（例: 1）を設定
5. 上部のデバイス選択からシミュレータ（例: iPhone 16）を選び ▶ で起動して動作確認
   - 起動直後に通知の許可ダイアログが出ます（「許可」で翌朝9時に通知が届くようになります）
   - 画面をタップして建物を建てると、実機では触覚が返ります（シミュレータでは振動しません）
6. 実機で確認する場合は iPhone を接続し、デバイスとして選んで ▶

---

## 5. App Store申請の手順

1. Xcode: 上部のデバイス選択を **Any iOS Device (arm64)** にする
2. **Product → Archive**
3. Organizer が開いたら **Distribute App → App Store Connect → Upload**
4. [App Store Connect](https://appstoreconnect.apple.com) で「マイApp → ＋ → 新規App」を作り、Bundle ID に `work.ltv.hiraku` を選ぶ
5. 6章の下書きを使ってアプリ情報を入力
6. スクリーンショットを登録（6.7インチ / 6.5インチ / 5.5インチ の3サイズ。シミュレータの ⌘S で撮れます）
7. ビルドを選択 → 「審査へ提出」

## 7. 審査で見られやすい点

### ガイドライン 4.2（最低限の機能）

WebView でサイトを表示しただけのアプリはリジェクトされます。本アプリは以下を満たしています（上の審査メモに書いてあります）。

- 完全オフラインで動作する自立したアプリ（three.js も同梱。ネットがなくても初回から動く）
- 端末内にセーブデータを保存し、毎日継続して遊ぶ設計（ログインボーナス・日替わりおねがい・おかえりボーナス）
- ネイティブのローカル通知・触覚フィードバックを実装

### 通知の許可ダイアログ

起動直後に通知の許可を求めます。断っても遊べます（通知が届かないだけ）。
審査員から「なぜ通知が必要か」を聞かれることはまれですが、審査メモに書いてあるので十分です。

### よくあるつまずき

| 症状 | 対処 |
|------|------|
| `pod install` でエラー / `npm run sync` が失敗 | `npm install` を先に実行したか確認。CocoaPods が古い場合は `brew upgrade cocoapods` |
| Xcode で "No such module 'Capacitor'" | `App.xcodeproj` ではなく `App.xcworkspace` を開いているか確認。それでも出たら `cd ios/App && pod install` |
| "Signing for App requires a development team" | 4章の Team 設定 |
| 1024px アイコンに透過があると言われる | 生成済みの `ios/App/App/Assets.xcassets/AppIcon.appiconset/AppIcon-512@2x.png` は透過なしです。差し替えた場合は透過なし PNG にしてください |
| 写真の「共有する」が反応しない | WebView の制約で共有シートが開かない機種があります。その場合は画像の長押し保存で代替できます（アプリ内に案内あり） |

## 8. アプリ内容を修正したい場合

アプリ本体は 1つ上のフォルダの `index.html` です（HTML・CSS・JS が1ファイル）。修正後、このフォルダで：

```bash
npm run sync
```

を実行すると、`www/` にコピー → three.js をローカル参照に書き換え → `ios/App/App/public/` に反映 されます。その後 Xcode で再ビルドしてください。

- アイコンを変えたい: `assets/icon.png`（1024px・透過なし）と `assets/logo.png`（スプラッシュ用）を差し替えて `npm run icons`
- three.js のバージョンを変えたい: `sync-web.sh` の `THREE_URL` を書き換え、`vendor/three.min.js` を削除してから `npm run sync`
- アプリ名・Bundle ID を変えたい: `capacitor.config.json` を編集して `npx cap sync ios`。Xcode 側の Bundle Identifier も合わせる
- バージョンを上げて再申請: Xcode の General で Version / Build を上げて、5章の Archive から

### フォルダ構成

```
ios-app/
├── package.json              npm設定（Capacitor + Haptics + LocalNotifications）
├── capacitor.config.json     アプリID・名前・WebView設定
├── sync-web.sh               ../ のWeb本体を www/ にコピーし three.js を同梱する
├── vendor/three.min.js       同梱する three.js r128（初回同期時に自動取得）
├── assets/                   アイコン元画像（icon.png 1024px・logo.png）
├── www/                      同梱するWeb資産（npm run sync で自動生成）
├── ios/App/App.xcworkspace   ← Xcode で開くのはこれ
└── 岩崎さんへの引き渡し手順.md  このファイル
```
