# 共有シートで画像を保存すると落ちる不具合の修正（ひらく島）

- 管理番号: #0011
- 種類: BUG（バグ修正）
- 対象: iOSアプリ（IOS）
- 作成日: 2026-11-06
- 関連: #0010（プライバシーマニフェスト・ビルド確認）

## 概要

iOS 版で島の写真を共有するとき、共有シートで「画像を保存」を選ぶとアプリが落ちる作りになっていた。写真に保存するときの説明文（`NSPhotoLibraryAddUsageDescription`）が `Info.plist` に無かったため。説明文を足し、ビルド確認で毎回確かめるようにした。あわせて、引き渡し手順の「必要な環境」を Xcode 26（Xcode 27 は使わない）・Node.js 20 以降に直した。

## 対象ファイル

- `ios-app/ios/App/App/Info.plist`（`NSPhotoLibraryAddUsageDescription` を追加）
- `.github/workflows/ios-build.yml`（説明文があることの確認を追加）
- `ios-app/岩崎さんへの引き渡し手順.md`（2章「必要な環境」、7章「審査で見られやすい点」に「写真への追加の許可」）

## 変更内容

### 写真の説明文

- 原因: アプリの画面から `navigator.share` で PNG 画像（`hiraku.png`）を共有すると、iOS の共有シートが開いて「画像を保存」を選べる。写真への追加には `Info.plist` の説明文が必須で、無いまま選ぶと iOS がアプリを強制終了する。審査で試されると、不具合（ガイドライン 2.1）として差し戻されるおそれがある。凪の池・そなえ帳・思考力には入っていたが、このアプリには無かった
- 直し方: `Info.plist` に `NSPhotoLibraryAddUsageDescription` =「島の写真を「写真」に保存するときに使います。」を足した。初めて保存するときに、この文で許可を求めるダイアログが出る
- ビルド確認: できたアプリの `Info.plist` にこの説明文が無ければ失敗にする（`.github/workflows/ios-build.yml` の Check app bundle）
- 引き渡し手順: 写真への追加の許可が出ることを、動作確認と審査の章に書いた

### 引き渡し手順の「必要な環境」

- 2章「必要な環境」の前の書き方: 「Xcode 15 以降が動く macOS」「App Store からインストールした Xcode」（いまは Xcode 27 が入ってしまう）「Node.js 18 以降」
- Xcode: **Xcode 26.x** を使い、**Xcode 27 は使わない**と書いた。理由: このアプリは Capacitor 7 のままで UIScene に対応していない。Apple は Xcode 27（iOS 27 の SDK）でビルドしたアプリは UIScene に対応していないと起動しないとしている。Mac App Store からは Xcode 27 が入るので、Xcode 26 の入手先（Apple Developer の More Downloads）と、Xcode 27 も入っている Mac での切り替え方（`xcode-select`・`open -a`）も書いた
- macOS ごとに使う Xcode の表: Apple の対応表で 2026-11-06 に確認。Xcode 26.4.1〜26.6 は macOS Tahoe 26.2 以降、26.3 までは Sequoia 15.6 以降で動く。macOS 27 で動く Xcode 26 は無いので、その場合は清武に連絡してもらう
- Node.js:「18 以降」→「20 以降」。Capacitor 7 の CLI（7.6.9）は Node.js 20 以上が必要で、18 では `npx cap sync` などが動かない（`package-lock.json` の engines で確認）
- そなえ帳・思考力の手順書と同じ書き方にそろえた
