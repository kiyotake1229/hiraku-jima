## 概要

Web版「ひらく島」を Capacitor 7 で iOS アプリ化した。`habit/ios-app/` を雛形に `ios-app/` を作り、three.js をローカル同梱して完全オフラインにし、ネイティブ機能として触覚フィードバックとローカル通知（翌朝9時の「今日のおねがい」）を組み込んだ。Xcode プロジェクトと CocoaPods の統合まで完了し、岩崎さん向けの引き渡し手順書（申請文面の下書き含む）を用意した。作成した Mac に Xcode がないため、Xcode での実ビルドは未確認。

## 変更内容

### 1. ios-app/ の作成（habit を雛形に）

- `appId: work.ltv.hiraku`、`appName: ひらく島`、`webDir: www`
- `contentInset: never`（本体が `viewport-fit=cover` と `env(safe-area-inset-*)` でノッチを避けているため）、`scrollEnabled: false`（ゲーム画面のバウンス防止。カード内のリストは内側スクロールなので影響なし）、`allowsLinkPreview: false`
- iPhone は縦画面固定。iPad は縦横対応のまま（マルチタスク要件のため）

### 2. three.js のローカル同梱（完全オフライン）

- `sync-web.sh` が `vendor/three.min.js` を `www/three.min.js` にコピーし、`www/index.html` の `<script src="https://cdnjs.../three.min.js">` を `three.min.js` に、`www/sw.js` のキャッシュ一覧も `./three.min.js` に書き換える。CDN 参照が残っていたら同期を失敗させる
- `vendor/` が空なら初回だけ `curl` で取得する。親の `index.html` は変えない（Web版は従来どおり CDN）
- 確認: `www/index.html` と本体の差分は three.js の参照1行だけ。ブラウザで `www/index.html` を開くと three.js がローカルから読まれ（REVISION 128）、コンソールエラーなしで起動した

### 3. ネイティブ機能（index.html）

```js
const NATIVE = !!(window.Capacitor && window.Capacitor.isNativePlatform && window.Capacitor.isNativePlatform());
const CAP = (window.Capacitor && window.Capacitor.Plugins) || {};
```

- `haptic(ms)`: ネイティブでは `Haptics.impact`。ms（配列なら最大値）が 30 以上で HEAVY、15 以上で MEDIUM、それ未満は LIGHT。Web では従来どおり `navigator.vibrate`
- `nativeScheduleQuestNotice()`: `boot()` の最後で呼ぶ。許可が未決なら要求し、id 2001 を取り消してから翌日 9:00 に「今日のおねがいが届いたよ」を1回予約する。起動のたびに予約し直すので、毎日開けば毎朝届き、開かなくなれば翌朝の1回で止まる
- Service Worker はネイティブでは登録しない（`!NATIVE` を条件に追加）
- 単体テスト（Node で Capacitor をスタブ化）: Web側 `NATIVE=false` で vibrate が従来の引数で呼ばれ通知は予約されない。ネイティブ側で 8→LIGHT / 12→LIGHT / 15→MEDIUM / 20→MEDIUM / [10,30,10]→HEAVY、通知は翌日 09:00 JST で予約された

### 4. アイコン

- `icon.svg` は角丸（rx=112）なので、iOS 用に `rx="0"` にした正方形版を `qlmanage -t -s 1024` で描き、PIL で `#3fa8e0` に合成して RGB（透過なし）にした → `assets/icon.png`。スプラッシュ用 `assets/logo.png` は角丸のまま透過で保存
- `npm run icons`（`@capacitor/assets`）で `AppIcon-512@2x.png`（1024px・透過なし）とスプラッシュ6枚を生成

### 5. Capacitor プロジェクト生成

- `npx cap add ios` → `npx cap sync ios`。`pod install` は完了し（Capacitor / CapacitorCordova / CapacitorHaptics / CapacitorLocalNotifications の4 pods）、`App.xcworkspace` に Pods が統合されている
- CLI の最後の `xcodebuild clean` だけが Xcode 不在で失敗するが、Pods の統合には影響しない（手順書に注記）
- `project.pbxproj` は `plutil -lint` で構文確認済み。Bundle ID `work.ltv.hiraku`、iOS 14.0 以上

### 6. 引き渡し手順書

- CLAUDE.md 7章の8項目（概要・環境・ビルド・署名・申請・申請情報の下書き・審査の注意・修正手順）を記載
